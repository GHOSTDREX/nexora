01

The pitch, in one breath

AgriNova is a multilingual, AI-powered smart-agriculture command center for small and marginal Indian farmers — a web dashboard that talks to a real field robot, AgriRover, and five trained machine-learning models, all in the farmer's own language.

It's not a mockup and it's not a single-language demo built for judges: it runs in 10 Indian languages, it drives real motors over real WiFi, and every number quoted anywhere in this app comes from a model actually trained on a real dataset — shown with its honest accuracy, not a marketing rounding-up.

Note"AgriRover" is the pitch name used throughout this document. In the codebase and firmware the robot is referred to plainly as the "robot controller" (device id ESP32_ROBOT_01) — same hardware, friendlier name for the room.
02

The journey

A real build history, not a rehearsed origin story — useful because judges probe process as much as output.

Foundations
Two disconnected Python prototypes
Started from an Irrigation Recommendation service (FastAPI + scikit-learn) and a separate rule-based Crop Suitability checker, plus an unused 2,200-row crop dataset sitting idle. No UI, no persistence, no hardware.
Platformization
Grew into a real multi-tenant web app
FastAPI + SQLAlchemy + SQLite backend with JWT auth and per-farm data isolation; React 19 + Vite + Tailwind v4 frontend. The two prototypes became two of what are now five ML routers.
Going physical
Wired to real hardware — three ESP32 boards
A motor-controller ESP32-S3, a sensor-node ESP32, and a dedicated ESP32-CAM. The dashboard stopped being a form-filling exercise and started driving actual actuators.
Pivot
Rainwater harvesting cut; fertilizer dispenser became a plow
A rainwater-harvesting feature was fully removed once it didn't earn its complexity. Once real hardware existed, a planned fertilizer-dispense mechanism was swapped for a plow actuator — the kind of change that only shows up once you're building against real motors, not a spec.
Debugging under pressure
Real firmware and infra bugs, traced and fixed
A speed-slider bug traced to firmware not re-driving the motor PWM on speed-only changes. WiFi credentials moved out of committed firmware into gitignored secrets.h files. A LAN/mobile-access chain (Windows firewall profile, a stray .env override, a wrong Python virtualenv) debugged end to end so the dashboard is reachable from a phone on the same network.
Pre-hackathon hardening
Security audit, fine-tuned disease model, WhatsApp bot, offline mode
A pre-hackathon audit caught a live DB migration bug via an automated Playwright test. The disease-detection model was fine-tuned (warm-start, not retrained from scratch) for better real-world-photo accuracy. Mandi price + dealer lookup, a WhatsApp bot, and offline-first PWA support were added in the final push.
03

Problem & who it's for

Small and marginal Indian farmers — the majority of Indian landholders — manage irrigation, fertilizer, and pest/disease decisions largely by habit and guesswork, in tooling that assumes English and assumes a desktop.

What's broken today

Irrigation is reactive, not data-driven. Fertilizer dosing is generic, not soil-specific. Disease identification means waiting for a visiting agronomist or guessing from a phone photo search. Government schemes and mandi prices are scattered across portals few farmers ever open. Almost all agri-tech tooling ships in English only.

What AgriNova replaces it with

One dashboard, in the farmer's own language, that watches soil moisture/NPK/weather continuously, tells them exactly when and how much to irrigate or fertilize, flags crop disease from a phone photo, and can physically act — water, plow, seed — through AgriRover.

04

How it works — architecture

Three tiers, two live loops. Nothing here is simulated end-to-end unless there's no hardware connected — and then it says so.

Frontend

React 19 · Vite · Tailwind v4

Framer Motion micro-interactions, react-i18next for 10 languages, Recharts for live sensor trends, a full Playwright E2E suite.

Backend

FastAPI · SQLAlchemy 2.0 · SQLite

JWT auth, per-farm multi-tenant isolation, WebSocket rooms per farm, SSRF-hardened outbound calls to hardware.

Hardware link

Plain HTTP, local WiFi

Backend polls the sensor node and relays dashboard commands to the motor controller — no cloud IoT broker, deliberately simple for a hackathon-grade LAN.

05

AgriRover — the physical robot

A 2-wheel differential-drive field robot with four actuator subsystems and a dedicated streaming camera, controlled by one HTTP command surface.

Drivetrain

ESP32-S3 controller

Two-wheel differential drive through a BTS7960 high-current driver, PWM speed control across a 0–255 range. Handles forward/back/left/right and live speed changes from the dashboard slider.

Implements

Two L298N driver modules

Water pump, plow (bang-bang actuation, ~100ms pulses), a stepper-style camera pan mount (±8 steps), and a seed dispenser running a continuous sweep motion.

06

Sensors

One sensor-node ESP32, polled by the backend roughly every 4 seconds over GET /sensors.

Environment

DHT22 — air temperature and relative humidity.

Soil

Capacitive soil-moisture probe — corrosion-resistant, direct-in-soil reading (vs. resistive probes that degrade over weeks).

Rain

Resistive rain sensor — feeds the irrigation model so it can hold off watering when rain is already falling.

Soil nutrients

RS485/Modbus NPK sensor behind a MAX485 transceiver — real nitrogen/phosphorus/potassium readings, not estimated, feeding directly into the fertilizer recommendation model.

Fully translated languages across every model's output

The disease-detection pipeline is a full decision system, not just a classifier: it runs an image-quality check (blur, brightness), a vegetation-readiness heuristic, then temperature-scaled calibrated inference (temperature 0.9857, confidence threshold 0.90) with a 4-state outcome — accepted, uncertain, image unsuitable, or subject unsuitable — so a blurry photo or a photo of something that isn't a paddy leaf gets an honest "can't tell" instead of a confident wrong answer.

The AI Farmer Assistant chat is Claude-powered with live farm context (this farm's actual sensor readings and crop) injected into every answer — and when no API key is configured, it degrades gracefully to a rule-based fallback covering 15 common topics in English, Hindi and Marathi, rather than the chat feature breaking outright.

08

Why it's better

The differentiators worth leading with when a judge asks "what makes this different from every other crop-app demo?"

1
10 fully-translated Indian languages
English, Hindi, Marathi, Gujarati, Kannada, Bengali, Punjabi, Malayalam, Tamil, Telugu — genuinely rare depth in agri-tech tooling, which usually ships English-only or bolts on one regional language.
2
Real hardware, not a mockup
AgriRover is a working 2-wheel robot with drive, pump, plow, seed dispenser and a live streaming camera — driven by the same dashboard a judge can click.
3
Graceful degradation everywhere
No hardware connected → labeled simulator, not fake "live" data. No LLM key → rule-based chat fallback. No Meta credentials → WhatsApp status honestly says "not configured" instead of pretending to work.
4
Per-farm multi-tenant isolation
JWT auth plus per-farm WebSocket rooms — this is architected as a real multi-farm product, not a single-user hackathon demo.
5
Security-hardened hardware relay
Outbound calls from the backend to the ESP32 boards are SSRF-guarded — a detail most student hardware projects skip entirely.
6
Automated end-to-end test coverage
A real Playwright E2E suite covers navigation, the disease-detection upload flow, WhatsApp settings, and PWA offline behavior — it caught a live DB migration bug before the hackathon, not after.
7
Offline-first PWA
Cached app shell and last-known sensor data so the dashboard stays usable on the patchy connectivity that's the norm in rural India, with a visible offline banner rather than a silent broken page.

Use cases

Remote monitoring

Check soil moisture, NPK, temperature and humidity from a phone without walking the field.

Water-saving irrigation

Irrigate on the model's recommendation, not a fixed schedule — accounting for rain already detected.

Multilingual accessibility

A farmer who has never used an English app gets the full experience in their own language.

Physical field work

Trigger pumping, plowing or seeding from the app — or let AgriRover run it on a schedule.

Always-on agronomy help

Ask the AI assistant a question about this specific farm's live conditions, any time.

Market & scheme awareness

Live mandi prices, nearest-dealer lookup, and matched government schemes — one place instead of five portals.
